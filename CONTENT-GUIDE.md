# Content guide — maintaining scholarship listings

All scholarship data lives in one file: **`src/data/scholarships.json`**. Edit it with any text editor (VS Code is free and highlights mistakes). After editing, run `npm run validate` to check it, then `npm run build` (or just push to GitHub if you deploy from there).

## Add a scholarship

1. Copy an existing record (everything between `{` and the matching `}`), paste it after the last record, and put a comma between records.
2. Change **every** field. Key rules:
   - `id`: next number, e.g. `"SCH-015"`.
   - `slug`: lowercase-with-hyphens, unique. Becomes the page address `/scholarships/<slug>/`. Don't change it later (it breaks shared links).
   - `countries`: slugs from `src/data/countries.ts` (e.g. `"germany"`). To add a new destination, add it to that file first.
   - `degreeLevels`: any of `bachelors`, `masters`, `phd`, `research`, `non-degree`.
   - `subjects`: `["any"]` or keys from `src/data/taxonomy.ts`.
   - `fundingType`: `fully-funded` **only if** official information describes tuition and living costs as covered. Otherwise `partially-funded`, `tuition-only`, `stipend-based` or `varies`.
   - `coverage`: write what the official source says. Use `null` when it doesn't say — the site will show "Not specified by the official source".
   - `featured`: `true` to show on the homepage.
   - `addedOn`: today's date, `YYYY-MM-DD`.
3. Run `npm run validate`.

## Edit a deadline / start a new cycle

In `dates`:
- `cycle`: e.g. `"2028/29"`.
- `cycleConfirmed`: `true` **only once the provider has published the new call.**
- `opens` / `deadline`: `YYYY-MM-DD` or `null`.
- `deadlineNote`: time and time zone, nominating-body warnings, etc.

The status badge is calculated automatically:

| Situation | Badge |
|---|---|
| `statusOverride: "varies"` (each university/programme sets its own date) | Deadlines vary |
| `cycleConfirmed: false` | Cycle not yet confirmed |
| `opens` is in the future | Opening soon |
| `deadline` has passed | Closed for this cycle |
| deadline within 30 days | Closing soon / Closes in N days |
| otherwise | Open |

Never copy last year's deadline into a new cycle.

## Mark a scholarship as closed

Usually nothing to do — once the `deadline` passes it shows "Closed for this cycle" automatically. To force it, set `"statusOverride": "closed"`. When the next round is announced, update `dates` and set `statusOverride` back to `null`.

## Update official URLs

- `urls.info`: the provider's official information page.
- `urls.application`: the official application portal **only if you have confirmed it**; otherwise `null`. When it's `null` the button reads "Visit Official Scholarship Website" and links to `urls.info`.
- `urls.sources`: every page you used to check the facts (`label` + `url`).

## Update verification

- `verification.lastChecked`: the date you checked, `YYYY-MM-DD`.
- `verification.level`: `official` (checked on the provider's own pages), `partial` (official partner/university or partly secondary), `needs-verification`.
- `verification.notes`: one sentence on what you checked.

The validator warns when a record hasn't been checked for 120 days.

## Verification checklist (for every new or updated listing)

- [ ] Found the opportunity on the **provider's own website** (not only a blog/aggregator).
- [ ] Provider name and programme name copied exactly.
- [ ] Eligible nationalities checked (e.g. is Pakistan on the list this cycle?).
- [ ] Degree levels and subjects checked.
- [ ] Funding coverage copied from the official text; nothing assumed.
- [ ] `fully-funded` used only if tuition **and** living costs are officially covered.
- [ ] Current-cycle dates published by the provider? If not → `cycleConfirmed: false`.
- [ ] Deadline time zone and any **earlier nominating-body deadline** noted.
- [ ] Application portal URL confirmed (else `null`).
- [ ] Special conditions (nomination, return-home rules, age limits) added to `warnings`.
- [ ] Sources listed; `lastChecked` and `level` updated.
- [ ] `npm run validate` passes; page checked in `npm run dev`.

## Erasmus Mundus programme finder

Two files power `/erasmus-mundus/`:

| File | What it holds | Who updates it |
|---|---|---|
| `src/data/erasmus-mundus.json` | All programmes in the official [EACEA catalogue](https://www.eacea.ec.europa.eu/scholarships/erasmus-mundus-catalogue_en): name, acronym, official website, EU project page | **Automatic.** Generated by `npm run sync:erasmus` (weekly on GitHub Actions). Don't edit by hand. |
| `src/data/erasmus-updates.json` | Intake dates and scholarship availability that **you checked on the programme's own website** | **You**, one programme at a time |

**Refresh the catalogue by hand:** `npm run sync:erasmus`. It reads the official catalogue pages only, saves a dated snapshot in `scripts/data/`, and rebuilds the JSON. If it finds fewer than 150 programmes (site down or layout changed), it stops and leaves the current list untouched. If the EACEA changes its page layout, the parser in `scripts/sync-erasmus.mjs` (`parsePage`) may need a small update. As a fallback you can edit the newest `scripts/data/erasmus-catalogue-*.txt` (one line per programme: `ACRONYM | name | website | EU project page`) and run `node scripts/build-erasmus-data.mjs`.

**Add checked intake dates for a programme:**

1. Open the programme page on your site (e.g. `/erasmus-mundus/emjmd-xyz/`). The last part of the address is its *slug*.
2. Open the programme's official website and find the admissions/application page for the **next** intake.
3. Add an entry to `src/data/erasmus-updates.json`:

```json
"slug-here": {
  "intake": "2027–2029 cohort",
  "opens": "2026-11-01",
  "deadline": "2027-01-15",
  "deadlineNote": "Erasmus Mundus scholarship deadline, 23:59 CET",
  "otherDeadlines": [{ "label": "Self-funded applicants", "date": "2027-04-30" }],
  "scholarships": "available",
  "scholarshipNote": null,
  "applyUrl": "https://official-application-portal.example",
  "sourceUrl": "https://the-official-page-you-checked",
  "verifiedOn": "2026-11-02"
}
```

- Use `null` for anything the official page doesn't state — never last year's dates.
- `scholarships`: `"available"`, `"none"` (programme says it has no Erasmus Mundus scholarships this intake) or `"unknown"`.
- `applyUrl` only if the official site links to a separate application portal; otherwise `null` (the button uses the programme website).
- When the deadline passes, the badge changes to "Deadline passed" automatically. Update the entry when the next intake is announced, or delete it to go back to "Check official website".
- Run `npm run validate` — it checks slugs, dates and URLs.

## Universities: English-taught degrees in Italy

| File | What it holds | Who updates it |
|---|---|---|
| `src/data/italy-programmes.json` | Every English-taught degree programme (and its university) from the Ministry of University and Research (MUR) open data | **Generated** by `npm run import:italy` — don't edit by hand |
| `src/data/italy-updates.json` | Requirements, fees and deadlines that **you checked on the university's own website** | **You** |

**Refresh the programme list (once a year, when MUR publishes a new academic year):**

1. Download from the MUR open-data portal (https://dati-ustat.mur.gov.it/):
   - "Offerta formativa" (corsi di laurea) CSV → save as `scripts/data/italy/mur-corsi.csv`
   - "Atenei" Excel → open it and *Save as CSV* → `scripts/data/italy/mur-atenei.csv`
2. Run `npm run import:italy`. It keeps only the newest academic year and only programmes whose teaching language includes English, and prints how many it found.
3. `npm run build` and redeploy.

**Add checked details.** Open the programme or university page on your site. The address gives the keys: `/universities/italy/<university-slug>/<programme-slug>/`.

University-wide rules (apply to all international applicants of that university) go under `"universities"`:

```json
"bologna": {
  "admissionsUrl": "https://official-international-admissions-page",
  "applicationFee": "€30 per application (non-refundable)",
  "tuition": "Based on family income (ISEE); international students ...",
  "englishRequirement": "B2 — IELTS 5.5 or equivalent, unless the programme requires more",
  "deadlines": [{ "label": "Non-EU applicants — 1st round", "date": "2027-01-31" }],
  "notes": null,
  "sourceUrl": "https://the-official-page-you-checked",
  "verifiedOn": "2026-11-20"
}
```

Programme-specific details go under `"programmes"` with the key `"university-slug/programme-slug"` and the fields `pageUrl`, `applyUrl`, `intake`, `duration`, `admissionRequirements`, `englishRequirement`, `tuition`, `applicationFee`, `deadlines`, `notes`, `sourceUrl`, `verifiedOn`.

- Use `null` for anything the official page doesn't state; a deadline can have `"date"` or, if it isn't a single day, `"text"`.
- The "Apply directly" button uses, in order: the programme's `applyUrl`, its `pageUrl`, the university's `admissionsUrl`, then the university website from the Ministry data.
- Run `npm run validate` before building.

## Other content

- Guides: `src/data/guides.ts` · Services: `src/data/services.ts` · Countries: `src/data/countries.ts`
- Legal pages: `src/pages/privacy-policy.astro`, `terms.astro`, `disclaimer.astro` — replace the *[Edit: …]* notes and have them reviewed.
- About page text: `src/pages/about.astro` (replace the dashed "Editable" box with your real story — no unverified statistics or testimonials).

## Build and redeploy

```bash
npm run build   # validate + build into dist/
```
- Cloudflare Pages / GitHub Pages connected to GitHub: commit and push — it redeploys automatically.
- Manual upload: upload the contents of `dist/` to your host.
